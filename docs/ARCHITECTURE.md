# 技术方案

## 选择

采用 Flutter，生成 Windows 桌面和 Android 原生宿主，共用 Dart 界面、棋规和业务逻辑。选择理由是双端一致性、文字缩放、语义可访问性及维护成本。不是网页套壳；暂不引入后端。

## 代码边界

- `lib/domain/xiangqi.dart`：不可变棋局、走法、合法性、局面键、终局；不导入 Flutter。
- `lib/domain/ai.dart`：有时间与深度上限的 alpha-beta 搜索；通过 isolate 运行。它只消费合法走法，不能各自实现棋规。
- `lib/application/game_controller.dart`：玩家行动、AI 请求代次、悔棋、保存恢复。新局、悔棋、退出使过期 AI 结果失效。
- `lib/infrastructure/game_store.dart`：本地保存，版本化 JSON；先验证再替换当前棋局。坏档不崩溃、不静默覆盖，显示可恢复错误。
- `lib/main.dart`：简体中文大字界面、自绘棋盘、可访问棋盘格、设置和确认。

AI 为自研轻量陪练，用迭代加深与子力/位置估值。完成一个深度后才替换结果，时间耗尽返回已完成的最好结果；无完成搜索时也必须返回合法备选走法。后续强引擎以 `AiEngine` 边界替换。根据本轮 APK 研究，优先评估公开 Pikafish 的 **UCI** 接口与 NNUE，另核对 Android ABI、线程数、内存和许可证；不要把 UCI 与 UCCI 混为一谈，也不要把第三方强引擎的棋力写成当前能力。

原版静态链路显示 Java 工作线程、引擎锁、命令发送与回复读取分离。吸收这一边界设计：未来引擎适配器独立管理初始化、模型文件准备、命令队列、超时/停止和退出清理。控制器仍须验证返回走法与当前棋局，并丢弃过期回复。原版参数不是本项目默认值的依据，尤其不能把 `Hash=16` 当成难度等级。

保存使用平台支持的应用私有存储，不申请共享存储权限。保存内容为版本、设置与可重放走法，恢复时从初始局面逐步校验，避免任意 JSON 棋盘绕过规则。写入队列串行化，防止旧快照覆盖新进度。进程被系统强杀时无法保证尚未落盘的最后一步，需实机验证。

## 仓库关系

```text
D:\projects\REA\
  rea-tools\       上游工具自己的 Git 仓库，保留 origin
  anxin-xiangqi\   本项目自己的 Git 仓库，可独立复制和维护
  .toolchains\     本机工具缓存，不属于游戏仓库
```

游戏代码不导入 REA、不通过相对路径依赖兄弟目录。研究证据可记录工具版本与摘要，原样本和含版权的提取物仅放在忽略的本地目录。

## 可验证性

规则测试覆盖棋种边界、送将、照面、将死与困毙；AI 测试检查合法性、终局与时间边界；控制器测试覆盖 AI 未完成时的悔棋/重开、保存恢复与坏档。界面测试覆盖窄屏和放大文字，不以测试通过替代真机验证。
