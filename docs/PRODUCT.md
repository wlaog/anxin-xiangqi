# 产品需求与边界

## 目标

核心用户是希望自己在电脑或手机上下几盘棋的长辈，包括视力下降、手部精细操作不便、对登录与复杂菜单不熟悉的人。陪伴者应能在一次简单说明后，让用户独立开局、走棋、悔棋、退出及继续。

主要场景：家中 Windows 大屏下棋；Android 手机随手下棋；来电、切后台或关闭窗口后继续。断网不影响全部首版功能。

## 首版体验

1. 打开看到棋盘、当前轮次和“点自己的棋子，再点要走的位置”。默认用户执红。
2. 选中棋子显示边框与合法落点，不仅依赖红绿颜色。误点己方其他棋子直接切换选择；非法落点保持棋局并给出可理解提示。
3. 用户走完显示“电脑正在想”，界面仍可响应。悔棋撤回到用户上一次落子前；电脑计算期间也能操作，旧结果不能覆盖新棋局。
4. 结束明确告知胜负或和棋，不自动开新局、不倒计时。重新开始须确认。
5. 自动保存当前进度；重新打开续局。写入失败应说明“这盘棋暂时不能保存”，继续允许下棋。
6. 使用设置中可选标准大字、1.2 倍和 1.4 倍文字，并继续叠加系统字号；走子提示、落子确认和减少动效自动保存。
7. 可选落子确认展示落子后的棋盘，框出准备走的棋子；取消不改棋局。放大棋盘支持继续下棋，棋格至少 60 逻辑像素，通过滚动条查看被放大的区域。

## 适老化验收目标

| 项目 | 目标与检查方式 |
| --- | --- |
| 普通文字 | 默认至少 22 逻辑像素；系统放大后功能仍可到达 |
| 主操作 | 触控区域至少 56×56；文字清楚，不用纯图标按钮 |
| 棋盘 | 手机优先占宽；窄屏可滚动，不能裁掉将帅或底部按钮 |
| 棋子 | 清晰中文、粗体、实体轮廓；红帅黑将、红兵黑卒等字形区分阵营 |
| 反馈 | 选中、上一步与合法落点形状区分；将军有文字提示 |
| 误触 | 新局可取消；允许悔棋；不因误点丢失棋局 |
| 认知负担 | 首屏一个棋桌；无轮播、签到、等级奖励、动态背景 |
| 可访问性 | 棋盘格有阵营、棋种、位置和选中状态的语义标签；需实测 TalkBack / Narrator |
| 操作节奏 | 无限时；AI 有等待文字和超时边界；动画不是操作前提 |
| 可用性 | 发布前至少邀请 3–5 位目标用户完成开局、走棋、悔棋和续局，记录实际问题 |

9 列棋盘在 360 宽手机上无法同时满足每格 48 像素的触控尺寸。不能声称小屏棋盘已达到该指标；需要通过大屏建议、横屏布局、可选棋盘放大/平移与实机试用改善。棋盘外按钮严格保持大触控区域。

## 规则范围

必须覆盖：九宫、将帅照面、马腿、象眼、象不过河、兵卒过河、炮架、车路径、不能送将、将军、将死、困毙判负。使用统一领域规则生成玩家与 AI 合法走法。

第二版取消按相同局面数量直接判和棋，使用公开 Pikafish 的长将/长捉责任识别，违规一方需换走法，无其他着法判负；双方允许不变的循环才可和棋，材料与无吃子判和同样交给引擎。详见 ENGINE.md，不宣称已经覆盖全部竞赛条款。不可把“吃掉将帅”作为唯一终局判定。

## 暂不纳入

账号、联机、聊天、好友、排行榜、商城、广告、订阅、云存档、在线 AI、腾讯接口兼容、破解付费、账号和协议逆向。已加入强引擎、执黑、翻转和可选落子确认；棋谱导入导出、残局库、声音/语音读棋仍需单独实现和验证。

当前迭代优先 Windows。原版网页人机对局已实测；Android / SDK 工作按用户要求暂停，不把共用代码测试当作安卓设备验收。

## 发布门槛

两端都须在断网下完成安装、开局、人机交替、悔棋、后台恢复、退出重启及完整终局；安卓至少覆盖一台低端真机，Windows 覆盖 125% / 150% / 200% 缩放。没有验证就不标记完成。安装包体积、AI 延迟和内存占用先实测，再制定可兑现的指标。
