# 本地引擎与裁决

第二版以公开 Pikafish 替换第一版的浅层 Dart 搜索。不是语言大模型，不访问 AI API。源码位于 Git 子模块 `vendor/pikafish`，固定提交 `ce9fb8391b32fa8aa3beefaa6ecdd1c1d438b185`；模型来源、字节数和 SHA-256 见 `assets/engine/manifest.json`。没有使用腾讯 APK 中的模型或库。

## 本机准备

```powershell
git submodule update --init --recursive
python scripts/fetch-engine.py
# 安装 CMake 与 64 位 MinGW-w64 GCC，并让下面两个命令可用
.\scripts\build-native.ps1 -Compiler 'g++.exe' -Make 'mingw32-make.exe'
flutter pub get
flutter test
flutter build windows --release --no-pub
```

已验证 GCC 14.2.0。上游当前源码使用的 128 位运算在本机 MSVC 14.43 构建失败，因此引擎单独用 MinGW 编译为 C ABI 动态库，Flutter Windows 外壳仍使用 Visual Studio。静态链接 GCC/C++/pthread 运行库，DLL 仅导入 Windows 系统库，不要求用户安装 MinGW。模型准备脚本按内容固定：远端 master-net 若被替换，会拒绝不匹配文件，维护者需显式评估新模型后再更新清单。

Android Gradle 用 NDK/CMake 编译同一桥接层与同一子模块，支持 arm64-v8a 与 x86_64，最低 Android 10（API 29）。首次启动将随包模型写入应用私有目录，采用临时文件再重命名；运行时不下载。Android 的 ABI/实机验证状态见 VALIDATION.md。

## 五档预算

| 档位 | 最多节点 | 最长搜索时间 | 接近最佳候选的分差范围 |
| --- | --- | --- | --- |
| 入门 | 1,200 | 350 ms | 120 cp |
| 轻松 | 8,000 | 650 ms | 70 cp |
| 日常 | 60,000 | 1,000 ms | 25 cp |
| 挑战 | 500,000 | 1,800 ms | 15 cp（仅开局） |
| 高手 | 不限节点 | 3,000 ms | 10 cp（仅开局） |

先达到节点或时间上限即结束。低三档使用 MultiPV 3，在同一完成深度中选分数接近最佳的合法候选；高档只在前 12 个半回合允许小幅变化。使用系统随机种子；不同开局并不保证每次都不同，不为变化刻意走非法棋。单线程、32 MiB Hash；模型加载和工作线程建立另有开销，时间预算不是整个调用的实时保证。这些名称没有 Elo 或腾讯等级对应，入门是否足够容易仍需长辈试下。

本机一次连续采样中各档完成 5/10/14/17/17 层，约 1,231/8,000/60,002/229,793/233,477 节点。不是跨设备棋力基准；置换表和时间预算会影响每次结果。八次入门开局采样出现两种不同中炮走法。

## 变着与终局

生产路径使用原生合法走法与 Pikafish 的 `Position::rule_judge`，完整回放初始局面和走棋历史，不能仅把当前棋盘传给引擎。对候选下一着再判断其是否形成单方长将/长捉责任；若形成，将该着标为禁着并要求变着。初始状态没有前驱，使用游戏裁决口径；其他重复候选使用搜索延续口径提前识别责任。这是本项目的变着策略，不宣称等同腾讯或完整竞赛条款。

无合法着法（含困毙）判负；禁着之外无棋可走也判负。允许双方不变的循环、引擎认定的材料和棋及无吃子规则交给同一裁决器。界面统一显示和棋，未单独细分材料/循环原因。纯 Dart `BasicRules` 只用于测试和开发，已移除“棋盘出现三次就和棋”的快捷判断。

## 异步与失败

FFI 搜索在工作 isolate 运行；原生搜索串行化，裁决器使用独立局面。悔棋、重开、销毁调用 stop 并递增任务代号，迟到结果不会写回棋局。暂时失败保留棋盘，可重试或悔棋，不再偷偷走第一个合法着法。发布包缺少库或模型时明确报错。

回归包含 44/1920 原生走法计数、长将变着、长捉变着、正常应将、允许的循环和棋、270 个半回合的跨实现走法比较、真实五档 NNUE 搜索和一步将死。还需扩大规则题库、执行双方长捉/将捉混合的竞赛用例和低端安卓性能验证。
